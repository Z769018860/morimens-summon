# morimens-summon

忘却前夜（Morimens）抽卡记录分析工具，门户名「忘忘看报」。当前已能从本机通讯中解出真实抽卡历史，按类别增量保存到本地数据库并导出 CSV/JSON。

## 忘忘看报：网页入口

`web/` 下是一组可以直接用浏览器打开（本地工具内置，或单独部署成静态站点）的页面：

| 页面 | 作用 |
| --- | --- |
| `index.html` | 主页：下载本地工具、进入欧非榜单、导入 JSON 看分析、链接到教程 |
| `analyzer.html` | 原本的抽卡数据分析页（总览 / SSR 时间线 / 限时卡池 / 概率与规则） |
| `leaderboard.html` | 欧非榜单：导入多份导出的 JSON，按平均出货抽数排名，只存在当前浏览器本地 |
| `guide.html` | 完整使用教程 + 隐私与数据安全说明 |

**隐私原则：** 本地工具读取当前游戏客户端的抽卡历史；历史响应含 playerId，用于自动识别 UID，不包含可登录账号的令牌。昵称由用户填写。网页版分析的 JSON 导入在浏览器本地解析；只有用户主动上传榜单摘要时才会发送资料。完整说明见 [guide.html 的隐私章节](web/guide.html#privacy)。

## 图形化分析

Windows 下双击 [start.cmd](start.cmd)，或运行 `python app.py` 后打开 `http://127.0.0.1:8765/`。页面只监听本机地址，从 `data/local/history.sqlite3` 读取已保存记录。下载包已包含对应的角色头像、竖版卡图和命轮图片，解压后无需再次下载图片。在线分析页也随部署提供这些图片。

- 分类别展示覆盖范围和 SSR 出货时间线，用横条显示每个 SSR 距离同类上次 SSR 的抽数；SR 等其他记录只计入抽数，不在时间线中逐条展示。缺页时不跨缺口推算。
- 总览另列观测 SSR 出率、平均出货抽数、确认 UP/歪次数、每类出货表现、有效 SSR 抽数分布，以及基于同批抽卡（相同时间戳）归纳出的成就标签：双黄、五连三金、连闪、保底之王、欧皇时刻、非酋警报。
- 展示 SKeyDB 的限时卡池开始、结束时间及持续天数，时间按 UTC+8。历史 RPC 没有返回确切卡池 ID；工具自动比对历史类别、抽卡时间和同期卡池，只有唯一匹配时才标记 UP 或“歪”；并行或资料缺失时显示“无法确认”，此时可在抽卡记录页用勾选框/下拉框手动排除记录或指定命中的卡池，选择会保存在本机浏览器并写入导出文件。
- “我的 Box”按角色和命轮展示网格卡片：角色使用竖版卡图，命轮使用对应图片；启灵/叠位与等级显示在卡片下方。点击角色启灵阶段可手动标记该角色的关键启灵，达到标记阶段后用暖金色高亮。关键阶段因角色而异，不会预设为统一数值。
- 展示可修改的概率与保底参考值，并根据有效 SSR 间隔给出娱乐性欧非观察。默认规则未经当前服务器游戏内概率详情核实，不能作为官方结论。UID 从抽卡历史的 `playerId` 读取；昵称由用户填写，二者在分析页显示并写入 JSON。
- 导出带覆盖信息、成就标签、玩家昵称/UID 的结构化 JSON（`schemaVersion: 5`）、CSV，以及信息更丰富的本地生成分享 PNG。导出的文件由用户自行保存或上传。
- 点击“自动更新”可查看准备说明、各类别覆盖进度与采集状态。若游戏仍在线但当前登录材料已从内存释放，页面会明确提示；点击“等待重新登录”后再重启游戏一次，程序会在三分钟内持续查找新会话并自动开始补页。遇到断线仍保留已完成页面。

**采集状态：** 解码、结构化保存和断点续取已验证。2026-10-01 的一次连接取得约 71 页后关闭。当前已运行较久的游戏进程中找不到完整登录材料，因此继续点击更新不能直接查询；等待新登录的流程已实现，但尚未完成一次重启后的端到端验证，自动取全仍不能称为稳定。已完整采集类别 1、2；类别 10、16 仍有缺页。页面会明确显示这些范围。历史响应字段只有 `itemTid/name/playerId/timestamp/type`，没有逐抽卡池 ID，故无法在并行活动中确定每一抽实际所属卡池。

## 当前事实

- 游戏抽卡历史走登录后的 `:8443` 自定义二进制通道；本机加速器转发时可从 `:12887` 捕获对应业务流。传输层已验证为 Sconn、会话密钥、RC4、LZ4、sproto、MessagePack 组合。
- 已确认 `type2RecordQueue`、保底计数等本地 Summon 状态字段，以及 `rewardList[index].tid/num`。
- 已解出真实 RPC `Summon.QuerySummonHistory`，请求参数为 `[历史类别, 页码]`，响应含总条数与逐条的 `itemTid`、`name`、`timestamp`、`type`。类别 2、1 已与角色、命轮历史画面交叉核对。
- 2026-10-01 实测已取全类别 1 的 80/80 条和类别 2 的 203/203 条；类别 10 为 120/505、类别 16 为 5/55、类别 17 为 0/0。类别 10、16、17 的具体含义尚待核对。

详细里程碑、数据模型、验证门槛见 [开发方案](docs/ROADMAP.md)。首批数据采集见 [数据获取步骤](docs/DATA_ACQUISITION.md)。

不启动游戏取得登录材料的单次验证结果见 [免启动登录验证](docs/NO_GAME_LOGIN_VALIDATION.md)：Steam 临时票据可取得，但目前尚未通过游戏网关认证。

## 本地录入原型

需要 Python 3.10+，不需安装第三方包。复制 [CSV 模板](templates/history.csv) 到个人数据目录，按数据获取步骤填写后运行：

```powershell
python summon_cli.py import "D:\个人数据\history.csv"
python summon_cli.py stats
python summon_cli.py export "D:\个人数据\history-backup.csv"
```

旧版 `summon_cli.py` 只提供手工 CSV 录入和条数统计。图形界面直接读取通讯采集记录，不依赖该手工录入表。通讯数据保存在 `data/local/history.sqlite3`，也可导出到 `data/local/history_all.csv`。

已保存数据的离线整理与覆盖情况：

```powershell
python fetch_all_history.py --local-only
```

游戏运行且当前登录材料可读取时，尝试在一次独立连接中补齐已发现类别；每页落盘，断线后保留进度：

```powershell
python fetch_all_history.py
```

该查询可能影响游戏现有连接。默认只使用当前进程的登录材料，不再回退使用旧抓包凭据。若账号历史在同步期间发生变化，程序会停止该类别以避免错位。

通讯数据自动获取的实验工具和验证条件见 [协议采集状态](docs/PROTOCOL_CAPTURE.md)。

## 产品原则

1. 每条记录保留来源和可信度，允许人工纠错。
2. 统计只基于已导入的记录，明确提示样本不完整时的影响。
3. 不保存或提交 Steam ticket、Cookie、Token、会话私钥、实际 RC4 key、原始账号抓包或未经检查的个人数据。
4. 协议研究与用户界面解耦；未验证的解析器不进入正式导入流程。

## 打包发布

`build_release.py` 把本地工具、`data/local/catalog.json` 和 `web/assets/` 图片打包成 `dist/morimens-summon-tool.zip`。打 `v*` 标签时 `.github/workflows/release.yml` 构建 GitHub Release；`.github/workflows/pages.yml` 每次部署时也构建一份放到 `web/downloads/morimens-summon-tool.zip`，主页可直接下载。包内不包含个人数据库、登录材料或抓包。游戏图片的权利归原权利人，仓库的代码许可不覆盖图片。
