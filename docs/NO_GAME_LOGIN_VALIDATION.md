# 不启动游戏的登录验证（2026-10-01）

目标：在 Steam 已登录、Morimens 未运行的情况下，验证本机工具能否取得游戏服务器认可的临时登录材料。测试不输入账号密码，不记录票据、Cookie、会话密钥或账号标识。

## 已完成的验证

1. Steam 客户端运行，Morimens 进程未运行。
2. 调用游戏安装目录的 `steam_api64.dll`，`GetAuthTicketForWebApi` 成功返回 234 字节临时票据；测试结束立即取消票据。
3. `GetAuthSessionTicket` 同样返回 234 字节票据；`RequestEncryptedAppTicket` 返回失败代码 2。
4. 2026-09-30 正常游戏登录抓包中的网关认证字段 `token` 是 1280 位十六进制文本，即 640 字节。游戏自带 `steam.dll` 对 `GetAuthTicketForWebApi` 的调用传入空身份参数；与第 2 步一致。长度差异不能仅归因于 identity 参数。
5. 用第 2 步的新票据构造一次网关认证请求，没有发送抽卡查询。服务端回复的匹配会话为空内容；旧正常登录抓包中的相应网关回复含 32 字节内容。当前票据没有通过与旧正常登录相同的验证门槛。

## 结论与下一门槛

可以在不启动游戏时取得一种 Steam 临时票据，但还不能据此完成 Morimens 网关登录或查询历史。票据长度差异提示游戏运行环境、Steam 授权上下文或上游身份交换仍有未确认环节；它并不能单独证明具体原因。

下一次正常启动游戏时，可只记录**票据长度、认证请求结构和网关回复形态**，与本次结果对照，不记录票据字节。若能在游戏关闭时取得相同形态的票据，再做一次网关登录和一页历史查询，并核对 UID 与本地保存记录。两个条件都成立才可宣称“无需启动游戏更新”。

Qookka 官方网页登录 handoff 的早期观测未发现抽卡历史 JSON 接口；这条路线仍需要单独验证其凭据能否换取游戏服务器会话。不要将账号密码输入本工具。
