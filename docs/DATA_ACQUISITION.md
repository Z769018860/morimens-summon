# 如何取得首批抽卡数据

当前可可靠取得的是**自己账号游戏界面展示的历史记录**。已有抓包只保存了加密后的业务数据；静态 AccountJson 样本能说明字段结构，不能替代当前账号的逐抽历史。

## 现在即可操作：游戏历史页转录

1. 登录自己的账号，打开抽卡历史。分别查看角色和命轮页面，从第一页翻到最末页；每页保存完整截图，画面要包含页面类别、页码、时间和每条结果。切换卡池时另建一组截图。
2. 复制 [CSV 模板](../templates/history.csv) 到仓库外的个人数据目录。每张截图用唯一的 `source_ref`，例如 `character-page-001-20261001`；一页里的五条结果填 `position=1..5`。`pool` 使用 `character`、`minglun` 或 `other`。
3. `pulled_at` 填界面显示的北京时间，格式为 `YYYY-MM-DD HH:MM:SS`；界面没有显示时留空。`name` 照界面原样填写。`tid`、`rarity` 没有可靠证据时留空，不要猜测。
4. 每录完一页，对照截图检查顺序、名称、时间和类别，再导入：

   ```powershell
   python summon_cli.py import "D:\个人数据\history.csv"
   python summon_cli.py stats
   python summon_cli.py export "D:\个人数据\history-backup.csv"
   ```

重复导入相同 `source_ref + position` 不会产生重复记录；默认也不会覆盖旧条目。发现录入错误时，先导出备份，再修改原 CSV 并运行 `python summon_cli.py import "D:\个人数据\history.csv" --replace`。不同截图若拍到同一条结果，需在导入前人工去重。保留截图和 CSV 在仓库外。数据库默认保存在被 Git 忽略的 `data/local/summons.sqlite3`。

## 补齐数据时需记录的元信息

- 账号所在区服、记录采集日期、页面类别与卡池标题。
- 页码顺序及是否翻到历史末页；有缺页就标记，不把统计当完整账号数据。
- 游戏界面显示的保底次数和规则截图，单独存档；不要从不完整历史反推精确保底。

目前 CSV 的 `pool` 只是界面类别，无法可靠表达具体卡池 ID。不同限定池混在一起时，在 `source_ref` 中保留卡池标题，待确认规则后再拆分。

## 自动获取所需的研究步骤

1. 在本人账号、合法授权的运行环境里取得 History 请求与响应的**应用层明文**，或完整验证从连接建立到逐帧解码的过程；仅有 44/45 字节密文请求不够。
2. 对照已记录的五页截图，逐字段确认 method、分页参数、history type、实体 ID、时间和结果条数；分别核实角色与命轮。明确异步推送、空页及客户端缓存。
3. 用不同会话、不同池和首尾页重复验证后，才编写只读自动导入器。导入前显示预览，让用户核对；出现未知字段时停止导入。

不建议继续靠包长猜记录、寻找固定 RC4 key，或假设网页账号接口和任意 UID 查询已存在；目前没有相应证据。
